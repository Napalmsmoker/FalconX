# ФАЛЬКОН — подготовка к защите

Этот материал описывает текущую реализацию. Он не заменяет отчёт об обучении:
ReID-обучение ещё не проводилось, а метки теста недоступны.

## Выступление на 2–3 минуты

«ФАЛЬКОН — сервис поиска визуально похожих транспортных средств в галерее.
Пользователь загружает кадр, выделяет один автомобиль и получает ранжированный
список кандидатов. Это задача Vehicle ReID: сопоставление одного транспортного
средства между изображениями, в том числе с разных камер. В режиме open-set
нужного автомобиля может не быть в галерее, поэтому сервис предусматривает отказ.

В основе текущего решения — предобученная на ImageNet модель ResNet18.
Последний классификатор удалён, а оставшаяся сеть формирует вектор из 512 чисел.
Вектор нормализуется до единичной длины. Галерея обрабатывается заранее при
запуске; её векторы помещаются в точный индекс FAISS IndexFlatIP.

Для нового запроса выполняется такой же кроп и предобработка. Индекс возвращает
наиболее близкие изображения по косинусному сходству. Если лучший результат
ниже порога 0.72, ответ содержит отказ и пустой список кандидатов. Иначе
возвращаются top-K кандидатов с оценками и превью.

Решение включает FastAPI, React-интерфейс, Docker Compose и отдельный скрипт
подготовки артефактов. Скрипт создаёт submission.csv, candidates.csv и
embeddings.npy в формате эталонного evaluator. Обработаны 1110 тестовых запросов
и 750 объектов галереи. Итоговая матрица признаков имеет размер 1860 на 512.

Проверены работа API, формат артефактов, нормализация и обработка ошибок.
Контейнеры запускаются, API проходит healthcheck. При этом текущее решение —
базовый вариант: модель не дообучена на vehicle ReID. При пороге 0.72 она приняла
все тестовые запросы. Поэтому качество open-set ещё требует улучшения:
следующий этап — обучение и калибровка на отложенных идентичностях из train.
Метрики на закрытом тесте без ground truth не заявляются».

## Что показывать во время выступления

1. Открыть localhost:3000 и показать подключение API.
2. Выбрать реальную фотографию, выделить автомобиль целиком. Избегать рамки
   только на крыше, дороге или фоне: модель сравнивает именно выделенный кроп.
3. Установить порог 0.72 и top-K=10, выполнить обычный поиск.
4. Показать top-1 и несколько следующих кандидатов. Объяснить, что сходство
   не является доказательством идентичности или калиброванной вероятностью.
5. Открыть localhost:8000/docs и показать GET /api/v1/health и POST /api/v1/search.
6. В PyCharm показать model.py, затем main.py, затем generate_submission.py.
7. Показать файлы в artifacts/. NPY — бинарный массив, не текстовый файл.

Демо-кнопки содержат синтетические сценарии. Если они используются, назвать их
демонстрацией интерфейса. Отказ в демо не доказывает качество отказов модели.
Изменение порога для иллюстрации механики также не является валидацией.

## Как проходит запрос

```text
Браузер: файл + BBox + threshold + top_k
    ↓ POST /api/v1/search через Nginx
FastAPI: проверка файла и координат
    ↓
Кроп автомобиля → RGB → Resize 256×256 → ToTensor → ImageNet Normalize
    ↓
ResNet18 без классификатора → 512 чисел → L2-нормализация
    ↓
FAISS IndexFlatIP → top-K по убыванию сходства
    ↓
best_score < threshold? → refusal, candidates=[]
                 иначе → matched, кандидаты и JPEG-превью
```

При старте галерея строится по test_gallery.csv. Изображения query и train
автоматически в неё не добавляются. Модель и индекс хранятся в памяти процесса.
При перезапуске индекс строится заново. Используется один worker сервера.

## Частые вопросы комиссии

**Что такое эмбеддинг?**
Вектор чисел, описывающий визуальные признаки объекта. В нашем случае это
512 float32-значений на один кроп. Он используется для сравнения изображений,
а не как гарантированно уникальный идентификатор автомобиля.

**Почему ResNet18, а не ResNet50?**
Для базового решения выбран сравнительно компактный предобученный backbone.
После global average pooling у него уже 512 признаков, поэтому не нужна
необученная проекционная голова. Это инженерный выбор, а не доказательство
превосходства по метрикам: сравнение архитектур не проводилось.

**Зачем L2-нормализация?**
Она делит вектор на его длину. Для двух единичных векторов скалярное произведение
равно косинусному сходству: score = sum(q_i * g_i). Поэтому IndexFlatIP подходит
для точного поиска по cosine. Score лежит примерно в диапазоне от -1 до 1;
он не является вероятностью того, что это один автомобиль.

**Что такое FAISS? Почему IndexFlatIP?**
Библиотека поиска по векторам. FlatIP сравнивает запрос с каждым вектором галереи
по скалярному произведению, не требует обучения индекса и даёт точный поиск.
Цена запроса растёт примерно как число объектов × размерность. Для 750 объектов
это понятный базовый выбор. Скорость на миллионе объектов не измерялась.

**Что значит open-set?**
У части запросов правильного автомобиля может вообще не быть в галерее.
Сервис должен уметь отказаться. Здесь правило — лучший score ниже порога.
Наличие правила не гарантирует качество: при 0.72 текущая модель не отказала
ни одному из 1110 тестовых запросов.

**Почему порог 0.72?**
Он задан в требованиях к реализации. На отложенной выборке он ещё не
калибровался. Нельзя называть его оптимальным. Калибровка должна использовать
отдельные идентичности и включать запросы без пары в галерее.

**Порог применяется к каждому кандидату?**
Нет, решение принимается на уровне запроса по лучшему score. При принятии
возвращается весь top-K, в том числе кандидаты ниже порога. При отказе список пуст.
Для submission ranking сохраняется даже при отказе, потому что это другой артефакт.

**Откуда vehicle_id и camera_id?**
Из доступных CSV-метаданных при совпадении image_id. У тестовых записей этих
меток обычно нет; API возвращает null. UI может показать image_id вместо
неизвестной идентичности. image_id — имя изображения, а не идентификатор ТС.

**Обучалась ли сеть на train.csv?**
Нет. Сейчас используются публичные ImageNet-веса. Чтобы обучить ReID, нужно
добавить соответствующий training pipeline, разделить train по идентичностям,
дообучить модель, оценить качество и заново сформировать артефакты.

**Какие метрики получены?**
Качество на закрытом тесте не измерено без ground truth. Проверены форматы,
L2-нормы, согласованность ranking с эмбеддингами, API и сборка UI. Три теста
прошли в Windows с временным обходом конфликта OpenMP. Позже отдельно проверен
запуск Docker и healthcheck; это не полный прогон тестов внутри Linux-контейнера.

**Что оценивает evaluate.py?**
submission даёт mAP@10 и Rank-1/Rank-5. Embeddings используются для полного mAP
и mINP. Candidates используются для precision, recall, F1, TNR и PR-AUC.
Rank-1 проверяет попадание верного объекта первым, Rank-5 — среди первых пяти.
AP учитывает порядок позитивов; mAP усредняет AP по оцениваемым запросам.
Точные особенности подсчёта берутся из предоставленного evaluate.py.

**Что такое junk-пары?**
В evaluator удаляются объекты с одновременно тем же vehicle_id и camera_id,
что у запроса. Другие автомобили той же камеры не удаляются. После этой
фильтрации запросы без позитивов не входят в ranking-метрики, но оцениваются
в режиме отказа. Тестовые метки закрыты, поэтому пайплайн их не угадывает.

**Есть ли автоматическое обнаружение автомобиля?**
Нет. BBox поступает из CSV либо выделяется пользователем. Детектор в текущую
реализацию не входит. Качество рамки влияет на признаки и результат поиска.

**Используются ли номерные знаки?**
OCR или отдельного анализа номеров нет. В описании датасета номера и лица
анонимизированы. Нельзя утверждать, что нейросеть математически игнорирует
каждый пиксель области номера: такого исследования не проводилось.

**Работает ли без интернета?**
Инференс с готовыми образами и весами работает локально. Первая сборка Docker
требует скачивания образов и зависимостей. Для полностью офлайн-переноса нужны
заранее экспортированные Docker-образы и доступный локально датасет.

**Где ускорение GPU?**
Модуль автоматически выбирает CUDA, если её поддерживает установленный PyTorch.
Текущий Docker-образ содержит CPU-сборку. В нём не заявляется GPU-инференс.

**Почему не показан Grad-CAM?**
В реальном API карты внимания не вычисляются. Поле отсутствующей карты равно
null, UI не показывает её. Синтетическая картинка в демо не является Grad-CAM модели.

**Кто разрабатывал решение, использовался ли ИИ?**
Отвечать по фактическому процессу: при подготовке кода использовался ИИ-ассистент,
использован предоставленный frontend и эталонный evaluator; сервис запускался
и проверялся. Не приписывать себе проведённое обучение, независимое написание
всего кода или проверки, которых не было. Форму раскрытия сверить с правилами.

## Команды перед демонстрацией

В терминале PyCharm, из корня Falcon:

```powershell
docker compose up -d --build
docker compose ps
```

Открыть http://localhost:3000 и http://localhost:8000/docs.
Обновить страницу после пересборки frontend. Если сервис не готов, посмотреть:

```powershell
docker compose logs --tail 50 backend
docker compose logs --tail 50 frontend
```

## Порядок передачи проекта

1. Получить точный адрес репозитория/площадки и требования организаторов.
2. Проверить, можно ли размещать CSV открыто. Изображения в Git не включены.
3. Подготовить обычный локальный commit текущего состояния. Commit сам по себе
   не публикует проект. Не менять даты и авторов для создания фиктивной истории.
4. Подключить точный удалённый адрес, проверить его и сделать push.
5. Проверить на сайте наличие исходников, весов, README и трёх артефактов.
6. Дать организаторам доступ, если репозиторий закрытый, и передать ссылку по
   официальному каналу. Публикация репозитория сама по себе может не быть сдачей.
7. Сохранить commit SHA версии, которая отправлена на проверку.

Если площадка принимает архив, использовать dist/falcon-submission.zip.
Архив содержит исходники, веса и результаты; фотографии подключаются отдельно.
Личный .env, история Git, настройки PyCharm и локальные кэши в ZIP не входят.
