# Подготовка ФАЛЬКОН к сдаче

## Текущее состояние

- API, FAISS-индекс, обработка BBox и экспорт реализованы.
- Docker backend и frontend запущены; healthcheck успешен.
- Веса ResNet18 ImageNet включены в weights/resnet18.pth (около 47 МБ).
- Артефакты сформированы для 1110 query и 750 gallery.
- Обучение на train.csv не выполнялось. Текущая модель — базовый вариант.
- При threshold=0.72 текущая модель приняла все 1110 запросов.
- Тестовые ground truth отсутствуют; mAP, Rank-1/5 и F1 не измерены.

## 1. Открыть исходники в редакторе

В Visual Studio Code: Файл → Открыть папку → выбрать папку Falcon.
Открывать нужно всю папку с backend, frontend и docker-compose.yml.
Перекладывать исходники в другую программу или перепечатывать их не нужно.
Редактор используется для чтения и изменения тех же файлов.

## 2. Проверить правила организаторов

Уточнить дедлайн, способ отправки, доступность репозитория для проверяющих,
допустимость публикации CSV/данных, требования к обучению, демонстрации и отчёту.
Сверить использование внешних весов и ИИ-инструментов с правилами мероприятия;
если требуется декларация использования, заполнить её фактически.
Не заявлять неподтверждённые результаты или обучение, которое не проводилось.

## 3. Если есть время на качество

Разделить train.csv на обучение и валидацию по vehicle_id, без пересечения
идентичностей. В валидации сформировать query/gallery с разными камерами и
запросами без совпадений. Дообучить extractor на train-части и измерить ranking
и open-set метрики эталонным evaluate.py на валидационной части.
Проверить отдельно заданный threshold=0.72. Если правила разрешают другой порог,
выбирать его только на валидации и документировать выбор; не подгонять по test.
После выбора модели повторно сформировать все три артефакта теми же весами.
Это план следующего ML-этапа, а не уже выполненная работа.

## 4. Проверить финальный пакет

Из корня проекта при работающем Docker:

```powershell
docker compose up -d --build
docker compose ps
docker compose exec -T backend python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/api/v1/health').read().decode())"
docker compose exec -T backend python generate_submission.py --output /app/artifacts
```

Команда генерации перезаписывает артефакты текущей моделью; выполнять после
окончательного выбора весов. После их замены старый validation.json нужно
пересоздать или убрать из пакета: он описывает предыдущий диагностический прогон.

Проверить: submission без заголовка, по 10 различных gallery_id; candidates с
заголовком query_id,gallery_id,confidence; embeddings float32 формы (1860,512),
сначала query, затем gallery в исходном порядке, с L2-нормами около 1.
Тестовый ground truth не изобретать. Для полного отчёта по закрытому test нужен
файл меток организаторов.

## 5. Файлы в репозитории

Отправить backend/, frontend/ (исходники), tests/, weights/resnet18.pth,
artifacts/submission.csv, artifacts/candidates.csv, artifacts/embeddings.npy,
README.md, SUBMISSION_GUIDE.md, DEFENSE.md, generate_submission.py, prepare_weights.py,
package_submission.py, evaluate.py, Dockerfile.frontend, docker-compose.yml,
nginx.conf, .gitignore, .dockerignore, .env.example, train.csv, test_query.csv,
test_gallery.csv. Если публикация CSV ограничена правилами, использовать закрытый
репозиторий с доступом организаторам либо согласованный ими способ передачи.

Не отправлять .venv, node_modules, кэши, .env с личным путём, весь каталог images
и локальные сборки. Фотографии занимают около 7.5 ГБ и подключаются отдельно.
Организатор помещает свой images/ рядом с docker-compose.yml либо задаёт
FALCON_IMAGES_DIR в .env. Датасет доступен по исходной раздаче организаторов.

Git-репозиторий инициализирован в Falcon. Репозиторий для передачи:
https://github.com/lygik123kir-sys/Falcon . При переносе в другое место
проверить адрес origin перед отправкой. Не придумывать историю изменений или авторство.
При отправке использовать собственную обычную Git-учётную запись.

## 6. Демонстрация

На localhost:3000 выбрать реальный кадр, обвести один автомобиль целиком,
установить threshold=0.72 и запустить обычный поиск. Верхние кнопки явно
демонстрационных сценариев не являются проверкой модели.
Показать API, top-10 и формат артефактов; для сдачи использовать CLI, не кнопки
экспорта в UI (кнопки теперь показывают инструкцию).

Неподтверждённые показатели FPS/размера галереи и заявление о подтверждении
идентичности убраны. Фактическая тестовая галерея содержит 750 объектов,
cosine score не является вероятностью идентичности. Явные демо-сценарии
содержат синтетические результаты и отмечены соответствующим предупреждением.

## 7. Что объяснить на защите

Путь запроса: изображение → BBox-кроп → Resize/Normalize → ResNet18 → вектор
512 → L2 → FAISS IndexFlatIP → top-10 → сравнение лучшего score с порогом.
Почему inner product после L2 равен cosine; почему неизвестные vehicle_id и
camera_id не угадываются; чем отличается отказ от ranking для submission;
откуда получены веса; какие метрики реально измерены и что пока ограничивает качество.

Проверить запуск из чистой копии на компьютере/сервере с Docker и доступным
датасетом. Первая сборка требует интернета; запуск уже собранных образов — нет.
Если организатор требует полностью офлайн даже сборку/перенос окружения,
дополнительно передать экспорт Docker-образов по согласованному каналу.

Записать финальный commit SHA, предоставить организаторам доступ к репозиторию,
отправить ссылку и артефакты по указанному ими каналу до дедлайна.

Переносимый ZIP можно подготовить командой `python package_submission.py`.
Это упаковка текущего базового решения, а не подтверждение выполнения всех
соревновательных критериев. Архив не содержит изображений и персонального .env.
